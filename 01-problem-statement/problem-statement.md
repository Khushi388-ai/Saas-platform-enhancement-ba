# Problem Statement

*Simulated case; all figures are illustrative assumptions.*

## Current situation
Personal-loan applications are taken at branches on paper forms. Customers visit twice (apply, then submit documents), staff re-key data into the core system, and customers have no visibility of status.

## Problems
1. **Slow turnaround:** assumed 7–10 working days from application to decision.
2. **High drop-off:** applicants abandon when asked to return with missing documents.
3. **Manual errors:** re-keying causes data mismatches and rework.
4. **No status visibility:** customers call the branch or helpline to ask for updates.
5. **Inconsistent eligibility checks** across branches.

## Objectives (SMART, assumed)
- Cut decision time to 3 working days within 6 months of launch.
- Reduce incomplete applications by 40%.
- Reduce status-enquiry calls by 50%.
- Apply one standard eligibility rule set across all channels.

## Success measures
Turnaround time, application completion rate, first-time-right rate, enquiry call volume, customer satisfaction.
